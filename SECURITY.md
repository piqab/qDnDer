# Security Policy

## Supported Versions

This is a solo-maintained project. Security fixes are applied to the latest release line on a best-effort basis.

| Version | Supported |
| ------- | --------- |
| latest 1.x | :white_check_mark: |
| < 1.0 | :x: |

## Reporting a Vulnerability

**Please do not open a public issue for security vulnerabilities.**

Use the **“Report a vulnerability”** button on the **Security** tab of this repository. This creates a private advisory visible only to the maintainer.

If that is unavailable, email me at **[your-email@example.com]**. You can find my contact details in the `LICENSE` file.

### What to include

To help me assess the issue quickly, please provide:

- A description of the vulnerability and its potential impact.
- Affected version(s) or commit hash.
- Step-by-step instructions to reproduce.
- A proof-of-concept or exploit code, if available.

## What to expect

As a single maintainer, I cannot promise fixed response times, but this is my honest best effort:

- **Acknowledgment:** I aim to confirm receipt within **7 days**. This is the only hard time-bound promise I make.
- **Triage:** I will assess severity and let you know whether I can address it.
- **Fix and disclosure:** Timeline depends on complexity. I will agree on a public disclosure date with you before publishing an advisory.

## Disclosure Policy

I follow **coordinated disclosure**. Please give me reasonable time to investigate and fix the issue before disclosing it publicly. I will credit reporters in the security advisory unless you prefer to remain anonymous.
